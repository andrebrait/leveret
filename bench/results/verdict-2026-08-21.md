Setup: leveret post-P5 (delta scan, profiles, all engines) + the review/verify agent
contracts executed by one Claude Sonnet review agent and one Sonnet verification
agent per PR. Blind: agents saw the PR title/body only, never the review threads.
Same 5-PR corpus as the baseline, replayed at the exact reviewed heads in the
dedicated mirror.

## What leveret found (all four confirmed with executed or cited evidence, 0 false positives published)

1. **#2444** — `--print-conf` legacy default emits a header directing users to
   `install-release.sh`, a script this very PR deleted the ancestors of. Confirmed by
   running both producers; a regression the PR itself introduced, reachable via the
   tool's own `--help` example, unguarded by the byte-identical test. **CodeRabbit
   missed it.**
2. **#2521** — doc claims image dirs are removed on workload exit; no code path does
   that (lazy `rm -rf` before the *next* pull only). **CodeRabbit missed it.**
3. **#2417** — `pkg-republish.yml` has no concurrency group and always publishes
   `direct`, so a manual dispatch mid-stage bypasses the gate-before-announce
   invariant the PR exists to create; the PR's own code comment concedes the race.
   **CodeRabbit missed it.**
4. **#2417** — the `noop != 'true'` guards can be deleted without failing any test —
   proven by an executed mutation probe on a /tmp copy (11 tests still pass with the
   guards stripped). Same *genre* as CodeRabbit's substring-assert catch on the same
   PR, different specific gap. **CodeRabbit missed this one too.**

The filter layers performed exactly as designed: 162+ pre-existing findings dropped
by delta on one PR alone, 24 zizmor leads class-graded `priced-noise` with
repo-grounded evidence (zero SHA-pinned Actions repo-wide; matrix source
branch-protected), 8 memory entries proposed with reasons and anchors, and one
reviewer refuted its own engine's typos leads ("mis-selected" is legit English).
Verification even exposed a leveret bug: engine status is computed pre-delta, so an
engine whose findings were all delta-dropped still reports `findings`.

## The honest verdict

**Recall against CodeRabbit's accepted set: ~0/22. The gate does not pass.**

leveret found four real, evidence-grounded defects CodeRabbit missed — the pipelines
are **complementary**, not yet substitutable. Where CodeRabbit's catches came from
and why leveret missed them:

- **Breadth per PR.** One review agent produced 0–3 deep concerns; CodeRabbit posts
  4–7 shallow-but-real ones. Our reviewer goes deep on the highest-signal thread and
  stops. pfBlockerNG's own landing flow runs THREE legs per PR; this benchmark ran
  one.
- **Cold memory.** ~4 of CR's catches were learnings-driven repo conventions (no
  gate-facing narration, durable references). leveret's memory started empty and its
  profile carried only the shellcheck scope. CR had months of accumulated learnings.
- **Test-honesty lens underweighted.** CR's Majors cluster in "this assertion can be
  satisfied vacuously" (pip3 bypass, locale probe, paths-vs-run match). Our single
  agent found exactly one of that class (#2417 R2, with a better proof than CR's).

## Next experiments before re-running the gate

1. **Three review legs per PR** (correctness / test-honesty / contract), mirroring
   landing.md — the single-agent breadth gap is the dominant loss term.
2. **Seed memory + profile from repo policy docs** before reviewing (the narration
   rule is written in the repo's own policy tree; the reviewer was never pointed at
   it).
3. Fix the engine-status-pre-delta reporting bug.
4. Then re-run this same corpus. Adoption (#2599) stays parked until recall holds.
