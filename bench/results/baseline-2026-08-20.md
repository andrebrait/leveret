# Baseline replay — deterministic layer vs CodeRabbit (2026-08-20)

Setup: leveret v0.1 (P2 profiles), engines semgrep/gitleaks/shellcheck/ruff/actionlint,
pfBlockerNG profile mirroring the repo's shellcheck scope. Corpus: PRs #2521, #2474,
#2471, #2444, #2417 replayed at the exact reviewed head (`refs/pull/N/head`), diff base
= merge-base with devel. CodeRabbit side: inline review comments by `coderabbitai[bot]`
on the same PRs.

leveret: zero findings, zero false positives. CodeRabbit: ~27 comments, ~24 distinct
findings, at least 22 of them accepted or acted on.

## Where CodeRabbit's catches came from

Classifying the 24 distinct findings by the capability needed to produce them:

- **~18 LLM-semantic** — logic holes (fail-open staging path, chmod skipped on the
  up-to-date branch, pipeline status masking a while-loop's last iteration), test
  honesty (assertions matchable by comments, coverage skipping the final list entry,
  vacuous locale probe), cross-file/workflow semantics (GitHub Actions jobs sharing no
  state, GNU-vs-bsdtar consumers). No static engine catches these; this is the P5
  review-agent's territory.
- **~4 repo-convention via learnings** — "no gate-facing narration in committed
  comments", durable-issue-reference style. CodeRabbit cites *learnt* rules from past
  PR exchanges — its memory pillar working exactly as our P3 design intends. One
  finding was **withdrawn after the author pushed back**, and the withdrawal cites a
  learning: memory drives both raising and retracting.
- **~2 deterministic-capable** — `subprocess` without `timeout` (a semgrep-expressible
  Python rule; not in `p/security-audit`/`p/python` defaults we run) and bare
  `python -m pytest` where the repo mandates `uv run` (a custom ast-grep/semgrep rule
  encoding a repo rule). Both are P4 candidates: custom rule packs, not more default
  rulesets.

Also observed: several CR comments embed an executed probe script ("Script executed"
analysis chains) — verification-by-execution, the same contract as our P5
verification agent.

## Conclusions for the roadmap

1. The deterministic layer is table stakes, not the product: on clean, gate-hardened
   PRs (this repo runs its own linters pre-push) default rulesets find nothing —
   correctly. Its value here is proving absence cheaply and catching regressions in
   repos without pfBlockerNG's discipline.
2. **P5 (review + verification agents) carries ~75% of CodeRabbit's value.** Priority
   confirmed.
3. **P3 memory matters more than P4 engines**: a sixth of the catches and the one
   graceful retraction both flow from learnings. Custom rule packs (P4) should be
   *fed by* memory (recurring priced findings promote to rules), not hand-authored.
4. Re-run this exact replay after P5; that run is the verdict, this one is the floor.
